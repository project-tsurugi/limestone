# get_partitioned_cursors(n) 設計メモ

## 概要

インデックス反映の高速化のため、snapshot クラスは複数の cursor を返すメソッド `get_partitioned_cursors(n)` を持ち、
n 本の cursor をそれぞれ別のスレッドで処理できるようにしている。

現在の実装は、スナップショットファイルとコンパクション済み WAL ファイルのロケータファイルを使って、キーの範囲で
スナップショットを領域に分割し、n 本の cursor が領域を 1 つずつ取って読む方式である。以前の実装 (1 本のスレッドが
スナップショット全体を走査し、エントリをキューでラウンドロビンに分配する方式) は、読み取りが 1 スレッドに閉じて
並列にならないため、この方式に置き換えた。

## 用語定義

| 用語 | 意味 |
|------|------|
| **ロケータファイル** | スナップショットファイルとコンパクション済み WAL ファイルのそれぞれに付く、データエントリの先頭位置を一定の間隔で記録したファイル (本体の名前に `.loc` を付けた名前)。形式と生成は `src/limestone/locator/` を参照。 |
| **レコード** | ロケータファイルの 1 つの記録 (本体のファイルの先頭からのバイト位置)。レコードの位置のエントリのキーは昇順である。 |
| **主ファイル・副ファイル** | 2 つのファイルのうち、レコード数の多いほうが主ファイル、他方が副ファイル。同数ならコンパクション済み WAL ファイルが主。コンパクション済み WAL ファイルがなければスナップショットファイルが主で副はない。 |
| **R** | 領域 1 つに含める主ファイルのレコード数 (`locator_settings::region_records`)。 |
| **領域** | 主ファイルのレコード j × R から (j + 1) × R の手前までの範囲と、それに対応する副ファイルの範囲、開始キーと終了キーの組。領域数は ceil(主のレコード数 ÷ R)。 |
| **領域の割り当て** | `region_allocator`。n 本の cursor が共有し、未処理の領域を 1 つずつ配る。 |
| **プローブ** | ファイルの位置を指定してエントリを 1 件読み、そのキーを取り出すこと。領域の開始キーと終了キー、副ファイルの範囲の二分探索に使う。 |

## 関数仕様

### シグネチャ

```cpp
std::vector<std::unique_ptr<cursor>> snapshot::get_partitioned_cursors(std::size_t n);
```

### パラメータ

```
引数 | 型 | 説明
-----|----|-----
n    | std::size_t | 返す cursor の本数 (1 以上)。
```

### 返り値

```
std::vector<std::unique_ptr<cursor>>

要素数は n。スナップショットにデータがなくても n 本返し、それらの next() はすぐに false を返す。
```

### 例外

```
種類 | 条件
------|-----
std::invalid_argument | n == 0 の場合
limestone_exception   | この関数が snapshot インスタンス上で 2 回以上呼び出された場合
limestone_exception   | ロケータファイルが不正な場合 (cursor の next() の中でプローブしたエントリが読めない場合を含む)
limestone_io_exception | ファイルを開けない、読めない場合
```

公開 API (`snapshot::get_partitioned_cursors`) は例外を捕まえて abort する。上記の例外は `snapshot_impl` の層のものである。

### 制約事項

- snapshot インスタンスごとにこの関数は 1 回のみ呼び出せる。
- cursor はすべて非スレッドセーフ。1 本の cursor は 1 つのスレッドが専有して使う。
- 返される cursor 群の担当する領域は互いに重複せず、全体でスナップショットのすべてのエントリを 1 回ずつ返す。
- 各 cursor の返すエントリはキーの昇順である。cursor 間の順序はない。
- 1 本の cursor が担当する領域の数は実行のたびに変わりうる (早く読み終えた cursor が次の領域を取る)。

### 備考

- 各 cursor は自分のファイルを `get_partitioned_cursors()` の中で開くので、その後にコンパクション済み WAL ファイルが
  削除されても (オンラインコンパクションが旧世代を削除しても) 残りの領域を読める。開いている最中に削除されると、
  開けなかった cursor で例外になる。
- cursor は snapshot の寿命に依存しない (領域の割り当ては cursor が共有して保持する)。ただし使用者は snapshot を保持する
  ことが推奨される。

## 実装

### 構成

```
snapshot_impl::get_partitioned_cursors(n)
  ├─ locator (スナップショットファイルの .loc)
  ├─ locator (コンパクション済み WAL ファイルの .loc。カタログにあれば)
  ├─ region_allocator (上の 2 つと R を持つ。n 本で共有)
  └─ cursor_impl × n (それぞれ log_entry_reader を 2 つ持つ)
```

1. 2 つのロケータファイルを読む (`locator`)。読む時点でファイルの大きさと照合し、不正なら `limestone_exception`。
2. `region_allocator` を 1 つ作る。主ファイルと副ファイル、領域数はここで決まる。
3. `cursor_impl` を n 本作る。それぞれがスナップショットファイルとコンパクション済み WAL ファイルを開く (fd は cursor 1 本に
   つき 2 つ)。領域はこの時点では受け取らない。
4. `cursor_impl` を `api::cursor` に包んで返す。

### 領域の範囲の計算 (`region_allocator::allocate`)

領域 j の範囲は次の順に求める。

1. 主ファイルの開始位置はレコード j × R の位置、終了位置はレコード (j + 1) × R の位置 (なければファイルの末尾)。
2. 開始キーは開始位置のエントリのキー (先頭の領域ではなし)。終了キーは終了位置のエントリのキー (最後の領域ではなし)。
3. 副ファイルの開始位置は、キーが開始キーより小さい最後のレコードの位置 (先頭の領域と、そのレコードがなければ 0)。
4. 副ファイルの終了位置は、キーが終了キー以上の最初のレコードの位置 (最後の領域と、そのレコードがなければファイルの末尾)。

3 と 4 は副ファイルのレコードをキーで二分探索する (それぞれ log2(副のレコード数) 回のプローブ)。副ファイルの範囲は
隣の領域と最大 1 レコード分重なるが、cursor のキーの範囲の判定で各エントリは 1 つの領域だけが返す。

ファイルの大きさはロケータの終端に記録された値を使い、fstat はしない。

### プローブ

プローブは、呼び出した cursor の `log_entry_reader` で行う (プローブ用の fd は持たない)。reader の読む範囲を指定の位置から
4 KiB に設定して 1 件読み、エントリがそれに収まらなければ (`short_entry`)、結果の `required` (解析に必要なバイト数) の分に
範囲を設定し直して読む。システムコールは pread だけで、ほとんどのエントリは 1 回で読める。

読めない (エントリの種類が不正、ファイルの大きさの中で読み切れない) か、データ系でないエントリなら、ERROR ログを出して
`limestone_exception` を投げる (ロケータファイルが不正な場合と同じ扱い)。

### cursor の読み方 (`cursor_impl`)

- `next()` の中で、今の領域に読むものがなくなったら `acquire_next_range()` で割り当てに次の領域を要求し、あれば 2 つの
  reader の読む範囲 (`set_range`) をその領域に設定して読み続ける。なければ `false` を返す。
- 領域の中では、両ファイルについて、開始キーより小さいエントリは読み飛ばし、終了キー以上のエントリに達したらその
  ファイルの今の領域を読み終える。
- マージの規則 (同じキーはスナップショット側、スナップショットの remove_entry はコンパクション済み WAL ファイルの同じ
  キーを打ち消す)、clear_storage による読み飛ばし、キーの昇順の検査は `get_cursor()` の cursor と同じである。
- reader のバッファ (16 MiB) は cursor が最後まで使い回す。領域を切り替えても確保し直さない。領域の切り替えで起こる
  システムコールは pread だけである。

### スレッド

`region_allocator` の書き換わる状態は次に配る領域の番号 (atomic) だけで、`allocate()` は複数のスレッドから同時に
呼べる。プローブは呼び出した cursor の reader で行うので、cursor 間で共有する fd やバッファはない。

### 読み込み量

主ファイルは領域の終了位置を越えて読まない (reader が読む範囲を終了位置までに限る)。副ファイルは二分探索で求めた
範囲だけを読む。領域 1 つあたりの追加の読み込みはプローブの分 (2 + 2 × log2(副のレコード数) 回、ほぼ各 4 KiB) である。
